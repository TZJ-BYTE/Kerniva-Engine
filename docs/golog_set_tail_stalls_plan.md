# 同步 SET 尖峰的逐请求诊断

2026-11-26 北京时间 06:51 开始。最晚 11:45 停开新窗口，12:30 封存。上一轮五臂实验、额外 AE/EA 复验和工作台 0.1.3 已独立验收。完整拓扑在 6,000 请求/s 下的增量未能稳定跨时段重现，主库单独运行也出现过尖峰。本轮回答同一条慢请求从计划发出到收到完整回复，时间消耗在哪一段。

## 执行和验收

1. Sol 用上一轮封存包复算 40 个正式窗和 4 个复验窗。保留全部 1,320 个计划秒，逐一核对 GET、SET 的分母、失败和累计延迟。以每秒成功 SET 的 p99 达到 100 ms 为触发，选取同窗最近的前、后非触发秒，对齐可证明同一时间轴的主从、标记和维护事件。列出不能从旧数据恢复的时间段。
2. 经 Astra 核对旧数据后，Sol 在独立 WSL ext4 目录用相同 gnet、strong/sync、合并上限 8、64 个连接、种子 42 和 100,000 键，运行 95% GET、6,000 请求/s 的 A 与 E 两种拓扑。A 仅主库和共用标记，E 含 Rust 维护、快照来源、两台从库和详细观察。每窗预热 5 秒、计划流量 30 秒。唯一性能锁覆盖所有窗口。
3. 新测客户端在开启采样时，以同一单调时钟记录计划时间、取出待发请求、开始网络交换及完成时间。均匀抽取约 1/16 的普通请求，另保留全部总耗时达 100 ms 的请求。逐连接、计划秒及命令核对分母和丢样，采样文件在测量后写出。同步采集来宾资源和源端计数，以及 Windows 的 CPU 与承载 WSL 的整块物理盘累计读写计数。宿主、来宾各自保留时钟桥和样本实际覆盖范围。
4. 技术校准共 8 窗，按 A 关开、开关，E 关开、开关做配对。每种拓扑的 SET p99 容限取 1 ms 与关闭采样时中位数的 15% 中较大者，p99.9 取 2 ms 与 25% 中较大者，成功速率允许相差目标的 2%。越线则由 Astra 决定是否仅开展观测扰动研究。失败、丢样和真实尖峰均保留。
5. 最多两期正式矩阵，每期 8 窗，开启和关闭采样的顺序反转。第二期起点距首期起点至少 45 分钟、距其末窗结束至少 15 分钟。重复现象需要同一拓扑至少两个独立的开启采样窗口，每窗均有触发秒、匹配的正常秒和同一请求的分解证据。结论注明覆盖范围、采样扰动、时钟误差及缺失证据。
