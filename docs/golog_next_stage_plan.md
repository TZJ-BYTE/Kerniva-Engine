## 实施边界

- `MSET` 及其他单条命令内的持久化批次按原子帧恢复。`EXEC` 持有执行排他门，每条成功命令有自己的提交。用实际命令和重启验证该契约。
- 单机正确性与同步边界先通过，再依据实测决定发布配置是否启用合并。过载窗口保留队列、失败率和延迟证据。持续运行及错误恢复使用独立测试目录。
- 复制初版按逻辑库维护序号，传输完整的不可变记录。连接中断后从已经验证并持久发布的位置继续。异步复制的主节点写入确认与副本追赶各自计量。

## 当前验收

Windows 与 WSL ext4 的项目竞态检测通过。同步写入对照中的合并版本达到 50% 写和 95% 读的两个目标。两个网络入口均完成三节点进程验证。从节点只读接口保留每个逻辑库的独立追赶位置。 [验收数据](golog_grouped_replica_report.md) · [复制决策](architecture/adr-0003-sealed-log-replication.md)

新键并发写已用 50% 全新键的固定负载确认。在线副本完成了已覆盖历史段回收与后续追赶。同步写的升压实验和 Rust 后台快照尾延迟对照均已记录。读取分别验收已有值、缺失键和需要清理的过期键。

按库独立轮询已通过双库限速和最多 16 库同时恢复的实测。真实副本现支持限制快照并发，默认保持 0。8 MiB/s 共享链路、混合大小快照的两对实验中，限 4 份时 B 峰值 RSS 分别变化 +3.41% 和 −12.88%，12 个轻库标记均在慢传输期间持久发布并可读。截断重试和恢复后断源重启也已通过。[逐轮数据与复现](golog_grouped_replica_report.md#真实副本上的快照并发上限)

副本恢复阶段的内存测量已完成。旧版 Go 逐行恢复的数据分配约 633 MiB，改为同步解码 Rust 行缓冲后，断源重启时降至约 283 MiB。默认并发下，真实一主两从实验的两对普通窗口分别降低 B 峰值 RSS 19.19% 和 24.32%，均约 39 秒追齐。60 秒时的常驻内存收益随配对方向变化。[内存曲线、故障与重启验收](verification/replica-recovery-memory.md)

16 库副本现按配置的库数保留到源端的空闲连接。两档固定轮询间隔、四组配对中，每次成功空拉取的分配均减少 40.3%–44.8%。默认 1 s 时，普通 B 的空闲分配从 0.263–0.291 降至 0.163–0.167 MiB/s，代价为多保留 14 条连接。32 个普通写入标记均持久发布并可读。16 个控制封存时刻的标记均在首次可取的轮次发布，普通窗口的最长 GET 延迟上界为 1,024.63 ms。[逐窗证据与复现](verification/replica-idle-polling.md)

每库复用 HTTP 响应读取缓冲区已验收。与连接池基线相比，每次空拉取再省 4,119–4,222 字节，16 库预热后多保留 65.375 KiB 缓冲和结构空间。32 个普通写入标记和 20 个定相位标记正确发布，后一组均在首个可取轮次完成。受限快照、64.02 MiB 无整形增量、截断重试、断源重启和双向混部通过。[保留量、逐窗结果与复现](verification/replica-reader-reuse.md)

大增量安装调查已完成。四个时段分别采集同一批封存文件的持久化耗时，第四时段后分别复验了增量截断和快照故障。生产沿用已验收版本。[最终报告、逐窗 JSON 和复现命令](verification/replica-install-latency.md)

内存分片列为后续研究。当前每个逻辑库有 256 个分片。今后可对比相同热键集中于一个分片和分散到多个分片的锁等待与尾延迟，再评估启动时选取分片数、自适应调整或其他并发模型。本轮沿用现有分片数。[分片定义](../internal/database/database.go)

## 后续性能验证

**固定速率实测已验收。** 两档各 4 个正式窗，共 108 万个请求，零失败。50% 写和 95% 读均达到原定速率门槛。完整拓扑下同步 SET p99 在四对中都增加了 0.705–1.114 ms。95% 读档的 GET p99 在两对中分别变化 +0.029 和 −0.053 ms。两从 48 次标记读取的延迟上界均在 133 ms 内。下一项针对同步 SET，把 Rust 整理、复制和观测开销分别列为对照，在相同输入及负载上判断能否重复这一差异，再决定是否有生产改动依据。[正式结果、逐窗数据和复现](verification/replica-live-load.md)

## 持续并发与恢复验收

已在 WSL 将并发写入、Rust 自动整理和异步复制放入同一验收场景。副本 B 在日志下载中断时强制重启，先读回旧游标，再用新快照和尾段追齐。终局确认活动日志中的已回复写入，强制重启主服务并逐键核对三个节点。gnet 和 net 的 60 秒负载均通过。

Rust 整理进程已支持有界地保留近期封存段。用同一版本配对跑四个 60 秒窗口时，每库保留八段的两个窗口都没有向持续在线的 A 安装快照，关闭保留的两轮有 40 和 14 次。启用期间每库额外保留约 0.5 MiB，落后较久的 B 仍通过快照和尾段恢复。 [故障验收与性能记录](golog_grouped_replica_report.md#保留近期已覆盖段)

百万键副本应用的复测已完成。使用同一主库、复制源、Rust 库和客户端，三对窗口各完成 30,000 次同步覆盖写。副本只改变一处新段应用调用，封存至应用 p95 的分轮中位数由 2,138.89 毫秒降到 104.31 毫秒，副本 CPU 由单核的 171.35% 降到 1.95%，峰值 RSS 由 2,279.52 MiB 降到 412.70 MiB。结论限于 WSL 本机已就绪副本的封存后应用。 [百万键复测](golog_grouped_replica_report.md#百万键副本重放复测)

## 热点负载对照

net 与 gnet 的 12 个读多写少窗口均通过，每秒 6,000 个请求、95% GET、64 TCP 连接。单热点提高了六对配对中的 GET p99，gnet 中位数由 1.43 升到 23.27 毫秒，net 由 1.42 升到 212.34 毫秒。纯 GET 的 12 个窗口也全部通过，各轮 GET p99 在 1.282 到 1.532 毫秒。单热点每次写入独立同步，合并批次为零。 [热点尾延迟](golog_grouped_replica_report.md#单热点键的读写尾延迟)

专用读写连接的 12 个窗口均通过。gnet 和 net 各有两对 GET p99 降低、一对升高，两个网络的专用连接都出现超过 100 毫秒的排队 p99。 [连接对照](golog_grouped_replica_report.md#单热点的专用读写连接对照)
