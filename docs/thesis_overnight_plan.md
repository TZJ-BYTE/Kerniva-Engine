## 1. 毕设只围绕一个问题展开

建议题目为《面向小键值混合读写负载的内存数据库读延迟优化设计与实现》。

核心问题是某条数据写入硬盘较慢时，其他无关数据的读取能否继续快速完成。

首轮研究对象为同步持久化模式、小字符串、GET/SET 混合访问、可完全放入内存的数据集。收益首先观察不同分片上的缓存命中读取，同一分片争用、冷读和复杂命令分别记录表现。

预期优势是降低慢写期间读请求的 p99，并说明实现代价。p99 表示 99% 的请求能够完成所需的时间。收益幅度通过实验确认。

## 2. 拟采用的设计

### Go 管理待提交状态和可见性

- 普通 SET 拥有操作私有的待提交值、预算预留和提交结果。
- 磁盘提交前，已提交的缓存值仍供允许并行的读取使用。实际锁粒度先采用分片，优先验证不同分片上的热读。
- 同一分片的写入保持有序。Rust 提交成功后，按统一流程发布缓存、WATCH 版本和变更通知，再返回成功。
- 提交失败时释放本次预算并返回错误，已提交的数据视图保持可读取。
- 新并发路径与当前数据库级 mutation 状态分别管理，避免并行操作共用整库回滚状态。
- 缓存未命中、类型变化、TTL 到期、预算不足、多键命令、EXEC、Lua、淘汰策略和生命周期操作使用经过审计的协调入口。切换入口时释放原锁并重新检查状态。
- 输入和输出仍采用明确所有权，跨调用保存的数据具有独立生命周期。

实现时先检查现有字符串入口、执行门和数据库锁。统一普通请求、TTL、Clear、Close 的锁顺序，避免写入等待持有热读取所必需的数据库级排他锁。复杂命令的执行隔离参与完整回归。

另需处理排队写锁造成的连带等待。Go 的 RWMutex 在写者排队后会阻止新读者进入，因此长期持读锁等待落盘仍可能通过周期 TTL 扫描间接阻塞其他 GET。TTL 扫描采用忙时延后或分片协调等方式，检查清理进度和读延迟。冷读回退、到期处理和复杂命令引起的全局协调等待单独测量并写明适用边界。

### Rust 提供提交与读取并行的基础

Go 热读阶段复用现有原子 WriteBatch、同步确认和恢复能力。随后用阻塞测试测量冷读是否仍受 Rust 同步等待影响。

若冷读等待路径得到证实，且本夜预算能够覆盖完整验证，则推进 Rust 锁拆分。

- 用写入串行锁保护 append、fsync、失败截断回滚和提交顺序。
- 用独立索引锁保护已提交索引，提交成功后短暂加写锁并整批发布。
- GET 在索引读锁内取得位置及文件句柄，随后定位读取并验证 checksum。
- checkpoint 捕获同一已提交边界，清理与段回收遵循快照引用和已持久化 checkpoint 的顺序。
- Clear、段轮换、snapshot、iterator、Close 参加同一套锁顺序和故障验证。

Rust 扩展的实施依据是现有等待路径和阶段验收结果。Go 热读隔离可以独立形成可评估的交付。

## 7. 性能实验

### 比较方式

核心对照为本轮开始时的实际 Kerniva 与优化后的 Kerniva。各优化阶段具有可独立运行的源码快照，用于说明收益来源。Redis 作为外部参照，在同等持久化确认方式和明确配置下安排测试。

外部参照优先使用已有的 Linux 虚拟机、WSL 或 Docker 环境，其可用性和配置独立记录。当前版本与优化版本的核心对照使用本机已验证的环境完成。

普通 SET 成功回复以同步提交成功为前提。测试同时记录写延迟、错误和超时。

### 核心矩阵

- 主实验采用 std 网络入口，gnet 进行代表性结果复测。
- value 为 32B，初始数据集为 10 万 key，数据集保持在内存容量范围内。
- GET/SET 比例采用 95/5、80/20、50/50。
- 每种比例先校准稳定容量，再使用原版与优化版均能接受的相同请求到达率比较。
- 每个配置至少重复 3 轮，每轮预热后测量 30 至 60 秒。记录实际请求样本量和运行时长。
- 版本交替运行，减少测试顺序影响。附加热点访问、同分片争用和百万 key 的代表性用例。
- 使用测试专用提交屏障或延时注入解释等待路径。注入方式与延时单独标注，常规设备结果使用关闭注入的 release 构建。

压测工具计划支持固定速率的混合 RESP 请求，并从计划发送时间计算等待和回复延迟，记录发生器排队、服务端响应、超时和拒绝率。实际发送率与目标速率分别输出。

### 输出指标

按 GET/SET 分别报告 p50、p95、p99、p99.9、吞吐、错误与超时数量。记录 CPU、进程常驻内存、Go 分配/GC 指标，以及可获得的锁等待和同步耗时。

性能评估关注相同到达率下读 p99 的稳定下降，并同时呈现写请求与资源成本。报告包含每轮数据及离散程度。收益未出现时，保留负结果、复现条件和解释，继续依据正确性和时间预算收敛交付。
