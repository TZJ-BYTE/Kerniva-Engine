# Go 增量日志与 Rust 快照无人值守计划

Kerniva 以 [ADR 0002](architecture/adr-0002-thesis-go-cache-rust-segments.md) 为当前开发路线。现有 Go 网络、命令和分片 KV 继续使用。写入日志全程在 Go 内执行，Rust 独立决定何时快照和回收，Go 只在启动恢复调用 Rust。已有 Rust 存储版本作为实验对照。

## 阶段与通过条件

| 阶段 | 自动执行项 | 进入下一阶段的条件 |
| --- | --- | --- |
| 1. 环境和基线 | 检查 WSL ext4、Go、Cargo、动态库、Redis 及空闲端口。记录环境和源码提交。为每组实验建立独立目录。 | 同机 Redis 和旧 Kerniva 能走真实 TCP 入口，关键配置经 INFO 或 CONFIG 核对。 |
| 2. Go 日志与 Rust 恢复 | 接通帧校验、提交序号、sync/none、按大小和时间封存、跨进程写者保护。Go 启动通过 ABI 装载 Rust 恢复的键值。 | 二进制值和原子批次往返一致。尾部截断恢复，损坏帧及缺号明示失败。第二写者被拒绝。在线路径的存储操作留在 Go。 |
| 3. 自主快照 | Rust 按封存字节量或积压年龄触发，选连续日志前缀，生成快照，再发布清单和清理。封存段与活跃段独立。 | 在 Go 持续更新时，Rust 发布快照并回收前缀。重启恢复同样的最新值、删除、类型和绝对 TTL。 |

| 6. 交付 | 同一个构建入口提供服务端、CLI、Rust 维护程序。保留启动配置、复现命令、结果与验收范围。 | 发出 PING/SET/GET，观察 Rust 自主快照，重启恢复数据，再核对报告数字与原始输出。 |

## 测试口径

- 小键值工作负载起点为 10 万键、32 字节值、64 个 TCP 连接及 95% GET。均匀键和热点键分别测。预热与测量分开，时段内固定到达率，收集 GET/SET p50、p95、p99、p99.9、实际吞吐、失败率、队列积压、CPU 和 RSS。
- 纯内存比较 Go RAM 与 Redis，无持久化。缓冲日志分别比较新 Go 日志、旧 Rust 分段日志、Redis AOF no。同步写分别比较 Go sync、旧 Rust sync 与 Redis AOF always。已有 Rust 内存同步原型作为额外参考时保持同等写入确认。
- 从双方可稳定达成的目标速率开始，再提高到达率观察饱和。重复轮次与种子对齐。报告有效窗口的配对延迟，过载窗口报告吞吐和错误。把纯内存、缓冲和同步分开讨论。
- 维护实验独立记录 Rust 的进程资源、快照截止序号、用时与回收字节。记录写入时的快照覆盖情况与重启用时，核对最终键值。Redis 的常态基线和显式维护实验分别标明实际配置及重写状态。

## 无人值守执行规则

使用独立数据目录、回环端口和构建产物运行。可自动换临时端口、单次重试可恢复的进程或依赖失败，重试留原始证据。环境需要人工干预时记录原因并继续可独立验证的步骤。正确性回归失败时保留现场并修复，再进入正式对照。每次运行输出至单独目录，进程通过独立句柄停止，旧数据目录用作历史版本时只读读取或复制。

当前版本先全量启动加载，在线请求走常驻内存。按需加载需要同时完成 Go 冷读和文件引用保护，列为后续验收项。启动验证和真实压测数据由当次实测报告给出。

## 复现命令

在 WSL 的 ext4 工作区执行，确保 PATH 中有 Go、Rust、C 编译器、Python 及 Redis。正式矩阵默认包含 6 轮、均匀键和热点键、3 种持久化策略与多档目标负载，基准阶段默认最多运行 12 小时。

```bash
bash scripts/golog-unattended.sh --profile formal --redis-rewrite
```

首次验证可运行 `bash scripts/golog-unattended.sh --profile smoke`。可使用 `--legacy-server` 和 `--legacy-library` 传入已冻结的旧构建产物。日志目录包含版本、测试输出、基准配置、各窗口原始结果和汇总。若基准阶段中断，可查看保存的计划并以同一参数和 `--resume` 重启 `scripts/thesis-golog-bench.py`。

恢复实验对同一批 10 万键执行两轮覆盖并删除一成，分别在快照前后执行 3 次重启。每次测从进程启动到 TCP PONG，随后逐键核对数据摘要。可用 `python3 -B scripts/golog-recovery-bench.py --output-dir ./logs` 单独执行。

将 `--maintenance-only --redis-rewrite` 传给 `scripts/thesis-golog-bench.py` 可单独运行四组维护对照。试验记录 Rust 自主触发的 `CURRENT` 切换和 Redis `BGREWRITEAOF` 的成功结束。两种机制均在测量客户端运行期间观察，触发条件及子进程样本写入各窗口日志。

可用 `--durabilities sync --workloads uniform --read-percent 50 --rate sync=3000,6000,10000 --no-maintenance --no-experiments` 单独复跑同步写压力梯度。持续积压和超时窗口用来判断该档承载能力。
