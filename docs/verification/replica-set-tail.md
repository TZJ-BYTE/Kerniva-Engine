# 同步 SET 尾延迟 · 两个时段的五配置配对

在 WSL 单机上让主库承受真实 gnet 流量，40 个正式窗共完成 **5,400,000 个请求，零失败**。50% 写、3,000 请求/s 和 95% 读、6,000 请求/s 两档，每个窗的四项速率都达到目标的 98%。吞吐达标时仍有短暂停顿。6 个窗的 SET p99 超过 100 ms，其中两个是只有主库的 A 窗。

针对 95% 读档做完额外正反序复验后，完整拓扑和主库单跑的 SET p99 分别相差 **+0.442、+0.934 ms**。两次均为正，但低于按四轮数据提前冻结的重复性阈值。本轮结论为吞吐与复制正确性通过，尾延迟归因未获复验确认。

冻结的生产基线为 `bf57829`，服务使用 Go 日志、同步强持久化和最多 8 帧的合并同步。本轮交付测量驱动、归因结果和可重放证据。数据库写入确认与故障恢复逻辑沿用已验收的实现。[上一轮完整拓扑对照](replica-live-load.md) · [本轮预定设计](../golog_set_tail_workbench_12h_plan.md)

## 五种配置怎样比较

A 运行主库和公共轻量观测。B 在 A 上加入 Rust 整理，C 在 A 上加入复制源和两从，D 同时启用整理和复制，E 在 D 上增加上一轮的完整观测。五种配置每窗各发 6 个 DB 0/1 标记，额外的主库标记命令共 1,332 个 RESP 请求字节。两期在每档内依次运行 ABCDE、EDCBA、CDEAB、BAEDC，第二期先跑 6,000/s。下表每格依次列出四个实测窗，单位 ms。

预登记要求同负载四个配对差严格同向，且差值中位数超过相同配置在正反轮间的波动阈值。6,000/s 的 E−A 是唯一满足这些条件的 SET p99 比较，四次分别为 **+1.032、+0.279、+710.935、+560.562 ms**，中位数 +280.797 ms，阈值 258.195 ms。该档 SET p99.9 差也四次为正，但每窗只有最慢约 9 个 SET 决定 p99.9。该档 GET p99 的 E−A 为 −0.070、−0.123、+652.214、+494.563 ms，方向随时段改变。

3,000/s 的 E−A 在第四轮改变方向。B−A、C−A、D−C、D−B、E−D 及两因素交互在两档均未达到预设的重复信号条件，因此当前数据无法把尾延迟归到整理、复制或额外观测中的一项。各条差值、阈值及有效配对数按负载和指标分别保存。

## 复制正确性与观测范围

240 个正式标记都在投递窗内写入并在终局读回。每窗校验 32 个主库工作集样本键，复制臂逐键对照两从及两个库的来源、内存序号和磁盘 `CURRENT`。每个启用整理的窗都观察到新的快照截止序号，每个启用复制的窗都观察到两个副本推进。总计记录 557 个投递窗内的截止序号变更区间。

只有 E 的 8 个窗运行高频探针。48 个标记有源端可取证据，每个标记对两从分别给出 GET 可见和磁盘 `CURRENT` 可见的时间上下界。额外的 48 次源端拉取共读 3,178,931 字节响应体。文件可见时间与目录同步完成时刻是两个不同的观测点。

北京时间 06:45，Astra 在查看复验数据前签准 6,000/s、E−A、SET p99 正向，两个新配对均须同向且中位数须超过原噪声阈值 **258.195456 ms**。四个新窗按 A、E、E、A 运行，每窗投递 30 秒。720,000 个请求全部成功，四个窗的负载与观测证据均通过。

| 顺序 | A 的 SET p99 | E 的 SET p99 | E−A |
