# 同步 SET 尖峰的逐请求诊断

## 旧窗口回答了什么

从上一轮封存包独立重放 40 个正式窗口和 4 个定向复验窗口，共有 6,120,000 次请求成功，覆盖 1,320 个计划秒。每秒按计划发送时间归组，统计到完整 RESP 回复为止的延迟。6 个窗口内有 38 秒的成功 SET p99 达到 100 ms。一个完整拓扑窗口占了其中 23 秒，4 个定向复验窗口均未触发。[逐秒复算与原始包校验值](replica-stall-seconds.json)

| 指标 | 38 个触发秒 | 同窗口最近的 19 个不同正常对照秒 |
| --- | ---: | ---: |
| SET 累计耗时中，客户端等待发送所占比例 | 79.45% | 14.69% |
| GET 累计耗时中，客户端等待发送所占比例 | 98.40% | 81.70% |

触发秒内共有 17,262 个 SET 和 195,738 个 GET，表中分子与分母均按实际请求数累计。前后对照共引用 63 次，部分使用同一秒。27 个具备快照观察的触发秒里，有 18 个完整包含一次已观测的快照截止序号推进区间。9 个具备相同观察条件的正常秒里也有 7 个包含此类区间。旧客户端按命令分别保存队列与总延迟的直方图，无法配对同一条慢请求的两段时间。[事件匹配与时钟范围](replica-stall-seconds.json)

## 新窗口怎样测量

使用实际 WSL ext4、gnet 和 strong/sync 的 8 帧合并上限。每窗 64 个连接，95% GET、5% SET，目标为每秒 6,000 次请求，预热 5 秒、投递 30 秒。A 只启动主库和共用标记，E 同时启动 Rust 维护、快照来源、两台从库及既有详细观察。每种拓扑对新探针作开关配对，同一阶段使用同一客户端二进制和相同种子。

开启探针时，客户端记录同一请求的计划发送、取出待处理请求、发起网络交换和完成时间。每窗按独立哈希抽取 11,228 个请求，并保留所有实际总耗时达 100 ms 的请求。普通样本和慢请求可以重叠。来宾系统的块设备、CPU、压力与主库计数，以及 Windows 承载 WSL 的整个物理盘计数，以约 1 秒间隔采样。每组计数差都保留采样区间和时钟误差。网络交换一段包含客户端、调度、传输和服务端等待。

校准 8 窗全部通过数据完整性核对，共 1,440,000 次请求成功。最后一个关闭新探针的 E 窗出现 2 个触发秒，整窗 SET p99 达 205.521 ms。另三个 E 窗的 SET p99 为 6.406–6.865 ms。配对差超过预设容限，Astra 将正式两期的判断范围定为采样扰动研究。开启探针时观测到的时间分解只直接适用于相应的实测窗口。[预登记方法和验收门](../golog_set_tail_stalls_plan.md)

## 两期正式结果

| 实测 | 窗口 | 成功请求 | SET p99 达 100 ms 的计划秒 |
| --- | ---: | ---: | ---: |
| 技术校准 | 8 | 1,440,000 | 2 / 240 |
| 正式一期 | 8 | 1,440,000 | 0 / 240 |
| 正式二期 | 8 | 1,440,000 | 0 / 240 |

两期正式首窗实际起点相隔 45 分 6.656 秒。16 个正式窗口的整窗 SET p99 为 **5.734–6.914 ms**，p99.9 为 **8.225–10.650 ms**，GET p99 为 **1.278–1.450 ms**。每窗按实际完成时间计算的成功速率为 5,999.54–5,999.99 请求/s。正式窗口内完成 2,879,975 次，其余 25 个请求在该窗停止投递后成功返回。[机器结果和配对差](replica-request-stalls.json)

三批总计 4,320,000 次请求全部成功，其中 4,319,968 次在投递窗内完成。12 个开启探针的窗口实际检查 2,160,000 个请求，保留 134,736 个普通样本，分连接、命令和计划秒核对丢样为零。全部开启探针的请求中，实际总耗时达到 100 ms 的 GET 和 SET 都是零。关闭探针的校准异常保留了直方图和原观察记录，但缺少同一请求的时间分解。旧 44 个窗及新 24 个窗记录的客户端 Go GC 次数和累计暂停均为零。

**验收结论**　旧证据确认在异常秒里积累了大量客户端等待。新证据验证了当前负载与这两个时段的正常延迟范围，仍缺两次独立、可逐请求分解的自然尖峰。数据库的持久化参数沿用原设置。Windows 宿主整盘计数、来宾块设备计数和快照水位仅能用于区间对齐与共同出现的检查。

## 复算

下载或拷贝两份同目录证据包 `Kerniva-SET-tail-20261126-evidence.zip` 和 `Kerniva-SET-stalls-20261126-evidence.zip`，解压后者，按包内说明运行离线重放。若已有新阶段原始证据目录，可从仓库根目录运行以下 PowerShell 命令。

```powershell
$run = 'logs/set-tail-stalls-20261126'
foreach ($stage in 'calibration','formal-1','formal-2') {
    python -B scripts/golog_stall_trace_report.py --root $run --stage $stage --out "$run/trace-replay/$stage.json"
}
python -B scripts/golog_stall_summary.py --root $run --out "$run/trace-replay/public-summary.json"
Get-FileHash "$run/trace-replay/public-summary.json"
```

公开摘要 SHA-256 为 `66ae02c8ea345dfd37605c5a35d7efab57b40ac5674018a364d86ac8f6d25881`。Windows 全库测试命令为 `go test ./... -count=1`；逐请求记录器的竞态检查为 `go test -race ./scripts/bench -count=1`。
